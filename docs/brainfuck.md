# Brainfuck

## 使用できる場所

- 通常提出、コンテスト提出、教材の練習問題。
- 問題作成・編集ページのテストrun。
- 教材Markdownの実行欄と作成者のライブプレビュー。
- 提出欄のテンプレート、エディターの構文色付け、提出の言語フィルター、プロフィールの言語別集計。

checkerのファイル読み取り・終了コードAPIはBrainfuckにないため、special judgeの作成言語は従来どおりC++・Python・Java・JavaScriptです。Brainfuckでの提出をspecial judgeで判定することは可能です。

## OJPの実行仕様

| 項目 | 動作 |
| --- | --- |
| 命令 | `>` `<` `+` `-` `.` `,` `[` `]` の8種類。それ以外の文字は無視 |
| セル | 30,000個の8bit符号なし整数。すべて0で初期化 |
| 加減算 | 255の次は0、0から引くと255 |
| 初期位置 | 一番左のセル |
| ポインター範囲外 | エラー。テープ端では循環しない |
| `,` | 標準入力の次の1バイトをセルに格納。EOFは0 |
| `.` | 現在のセルの値をそのまま1バイト出力。改行は自動追加しない |
| ループ | 現在セルが0なら `[` から対応する `]` の後へ移動。0でなければ `]` で対応するループに戻る |
| 構文チェック | 実行前に全体の角括弧を検証。対応しない括弧は提出ではCE、教材では実行エラー |
| 実行状態 | ケース・実行ごとにセルと入力位置を初期化。以前の実行から持ち越さない |

`12` という入力は整数12ではなく、文字 `1` と `2` のバイトです。整数として計算するにはプログラム側で変換します。UTF-8の日本語は複数バイトになります。提出結果は生バイトで比較し、教材はUTF-8として表示します。教材で不正なバイト列を出すと置換文字が表示されます。

## 例

提出欄にはHello Worldのテンプレートを入れています。次はEOFまで入力をそのまま出力する例です（入力途中に値0のバイトを含めない場合）。

```brainfuck
,[.,]
```

教材では `run` と一意の `id` を付けます。

````markdown
## 入力をそのまま出力する

```brainfuck run id=bf-echo
,[.,]
```
````

教材作成画面の「brainfuckのコードセルを挿入」ボタンでも追加できます。標準入力の初期値・コード編集可否は既存のセル設定で指定します。教材ZIPにも同じ設定を保存できます。

## 実行制限

- 提出は独立したNode.jsプロセス内のインタープリターで実行します。BrainfuckソースをJavaScriptとして評価しません。ファイルを読み取る独自命令なども追加していません。
- 問題の時間・メモリ制限、既存の出力・プロセス数・作業領域制限を適用します。テープ範囲外はRE、無限ループはTLEです。メモリ表示はテープだけでなくNode.jsプロセスを含みます。
- 入出力は固定長のバッファで処理し、大きな入力全体や出力全体をメモリに保持しません。構文チェック用の領域はソース長に比例します。
- 教材は既存の隔離iframeとWorker内で実行し、10秒で停止、出力は最大64 KiBです。停止・タブ離脱でもWorkerを破棄します。Pythonの実行環境を読み込む必要はありません。
- サーバーの `JUDGE_SANDBOX` 設定は変更しません。既存のbasicモードが完全隔離になるわけではありません。

## 導入

追加のaptパッケージやConfig Varsは不要です。既存のNode.jsを使用します。既存DBには言語enumへの追加だけを適用します。

```bash
npm ci
npm run db:generate
npm run db:brainfuck
npm run build
```

`db:brainfuck` は `prisma/brainfuck-schema.sql` を実行します。同じSQLを再実行しても重複追加しません。既存の問題・提出の変更やseedは不要です。新規の専用開発DBでは通常のスキーマ作成でもBrainfuckが含まれます。本番ではバックアップと別DBへの復元確認後に適用し、web・workerの両方をデプロイしてください。

## 検証

```bash
npm run test:brainfuck
npm run test:learning
npm run test:i18n
npm run test:judge
npm run lint
npx tsc --noEmit
npm run build
```

`test:brainfuck` は8bit循環・境界・UTF-8・EOF・構文・バッファ境界と、実際のジャッジ処理でAC/WA/CE/RE/TLE・出力制限を確認します。教材のテストは生成されたiframeのスクリプトとWorkerソースをNode.jsの検証環境で実行し、UTF-8出力、エラー、出力上限、停止タイマーを確認します。これは本番ブラウザを操作した受講テストとは別です。
