# 自動保存・問題検索・版管理・復習

4機能をこの順番で追加しています。既存の問題ID・ユーザーIDは変更せず、
タグ・版履歴・個人メモはAppStateではなく専用テーブルを使います。

## 1. 自動保存と復元

対象は通常提出のコード、問題作成・編集、保存前テストのコード、教材作成・編集です。
ログイン中の利用者IDと、問題・教材・コンテスト等の文脈ごとに保存を分離します。

- 保存先はブラウザのIndexedDB。この機能だけで入力内容をサーバーへ送信しません。
- 約800msの入力待ち後と、フォームを離れるときに保存を試みます。
- 再訪時に下書きがあれば「復元」「破棄」を選べます。勝手に現在の内容を置き換えません。
- サーバーの基準更新日時が変わっていれば、復元内容を確認するよう警告します。
- 別タブが更新した下書きを未確認で上書きせず、保存を停止して復元候補を表示します。
- サーバーへの提出・保存が成功したときだけ、そのフォームの下書きを削除します。
- 1件の上限は2MiB、有効期間は最終保存から14日です。
- ZIP本体は保存しません。ケース・サンプル本文は合計約512KiBの範囲で保存します。
- 大きな本文を省略した復元データは、そのまま更新できないようにします。元のZIPを再選択すると、
  復元済みの問題文・checker・小ケースの編集を保ち、不足する本文を補います。名前が一致しない場合は失敗させます。

ブラウザの保存領域が利用できない・容量不足の場合は警告し、手動保存・ZIP出力を案内します。
ブラウザの強制終了直前の入力や、端末データ削除まで保証するサーバーバックアップではありません。
共用端末では下書きの破棄やブラウザデータの管理に注意してください。
既存の教材受講用コード・クイズのブラウザ保存は変更していません。

## 2. 問題検索・タグ

`/problems`の検索フォームで以下を組み合わせられます。画面は50件ずつ表示します。

- タイトル・識別名・タグの部分一致検索
- タグの完全一致、難易度の下限・上限
- 自分の未挑戦・挑戦中・正解済み
- 自分のブックマーク

解答状況は専用runtimeテーブルの確定状態も読みます。同じ問題にWAがあってもACを優先します。
検索結果の対象は既存の公開範囲・権限制御で閲覧可能な一覧だけです。
タグを経由して他人の非公開問題を見つけられる仕様にはしません。

問題設定タブからタグを編集します。作成者・管理者のみ変更でき、20個まで・各40文字までです。
NFKC正規化・前後空白除去・英字小文字化・重複除去を行います。
カンマ・読点・改行で区切れます。ZIPの`config.json`の`problem.tags`にも対応します。

```json
{"problem":{"tags":["dp","グラフ"]}}
```

既存ZIPにtagsがなければ既存タグを消しません。空配列は明示的なタグ解除です。
APIの`GET /api/problems`も`q`、`tag`、`min`、`max`、`progress`、`saved`を受け付けます。
個人の解答状況・ブックマークのAPI絞り込みにはログインが必要です。

## 3. 版履歴と判定条件の固定

編集画面の「版履歴」で、問題文・設定・タグ・パッケージの保存履歴と差分を確認・復元できます。
初回は50件を表示し、「さらに以前の版」で過去を読み込みます。本文の比較表示は各項目の冒頭400文字です。
版のID・SHA-256・保存日時を記録し、同一内容は重複記録しません。
版履歴の閲覧・復元は現在の作成者・管理者だけに許可します。

- R2の問題は、問題文・設定のスナップショットとZIPの固定参照を保存します。大きなZIP本体をDBに複製しません。
- R2を使わない旧形式の問題は、互換のためinlineパッケージも版へ保存します。
- 新しいR2キーにはUUIDを付け、条件付きPUTで上書きを防ぎます。ETag付き参照のGETでは差替えを検出して失敗させます。旧ETagなし参照は互換動作です。
- 更新時に旧ZIPを自動削除しません。これにより**R2の保管容量は増えます**。
- 導入後の提出受付時に、問題文・実行制限・テスト・checker/interactorの版を固定します。
- キュー待ち中に問題が変わっても、workerは固定版を使います。
- 再ジャッジは既存仕様と同じく「要求時点の最新版」が標準です。「最初の提出時の版」も選べます。
- 提出詳細に最初の版と判定版を表示し、再ジャッジ要求にも使用版を記録します。
- WJ表示のケース一覧も判定に固定された版から取得します。
- 復元前の状態も履歴に残し、既存提出の固定版は変更しません。

導入前の過去の版は復元できません。旧提出には「版の記録なし」と表示します。
旧提出は最新版で再ジャッジできますが、記録のない原版を指定すると拒否します。
元のProblemはAppStateに残っているため、問題文保存・タグ保存・パッケージ反映はそれぞれの保存段階として記録します。
画面全体の保存・公開を単一トランザクションにする機能ではありません。
問題そのものを削除した後のごみ箱・復元機能は今回の対象外です。

## 4. ブックマーク・個人メモ・復習

ログイン後の問題ページ下部で、ブックマーク・復習対象・復習日・個人メモを設定できます。
チェックや文章を編集した後に「メモ・設定を保存」を押してください。
メモは10,000文字まで。復習日は日本時間で扱います。

ヘッダーの「ブックマーク・復習」から`/review`を開きます。
復習期限到来、ブックマーク、保存したすべての問題を切り替えられます。
復習日が未指定の復習対象は、その日から一覧に出します。
「復習済みにする」で復習対象・日付を解除し、ブックマーク・メモは残します。
公開範囲の変更等で閲覧できなくなった問題は表示しません。

APIは常にセッション本人のIDを使い、body内のuserIdでは保存先を変えません。
他人・ゲストの問題ページやAPIへメモを混ぜず、個人用GETにはprivate/no-storeを指定します。
新しい小さなJSON APIは64KiBで入力サイズを制限します。

## 導入

追加SQLはテーブル・インデックスの作成のみです。既存行・AppState・R2オブジェクトの書換えは行いません。

```powershell
npm run db:workspace-features
npm run db:generate
npm run build
```

本番への適用は、バックアップ・復元検証の後に実施してください。
workerの処理を完了させて停止し、新しいWebとworkerを揃えてからworkerを再開します。
旧workerは版IDを認識しないため、混在期間に新しい提出を処理させないことが重要です。
DBのセットアップ前は新規版の記録・提出を503で止め、DBエラーに秘密のケース内容を含めないようにします。

## 検証

```powershell
npm run test:workspace
npm run test:workspace:integration
npm run test:i18n
npm run test:judge
npm run test:interactive
```

単体・React hook・SSRテストではIndexedDBの再読込、アカウント分離、別タブ競合、容量上限、離脱直前の入力、
ZIP再選択による大きな本文の復元、タグ・検索・進捗・復習、版のハッシュと差分、日英表示を確認します。
IndexedDBはfake-indexeddb、hookはReactと同じ19.2.3のテスト用rendererを使用します。

HTTP統合テストは`WORKSPACE_TEST_ORIGIN=http://127.0.0.1:3102`と、
`WORKSPACE_TEST_DATABASE_URL`のDB名`ojp_workspace_test`・接続先localhostのみで実行できます。
通常のWeb・worker・APIを使い、キュー待ち後のパッケージ差替え、原版AC・最新版WA・原版再判定AC、
履歴からの復元、旧inlineケースの保持、他人のメモ・タグ・履歴の権限を確認します。
CIにも専用のPostgreSQL環境を追加しています。本番環境へテスト用の認証状態を持ち込むものではありません。

R2の条件付き操作は [Cloudflare公式仕様](https://developers.cloudflare.com/r2/api/s3/extensions/) に合わせています。ストレージ操作の単体テストはSDKをmockし、本番R2へ送信しません。

## この実装の検証結果

- 新機能の単体・hook・SSR・SDK mockテスト16件が成功。
- 使い捨てPostgreSQLと通常のWeb/workerによるHTTP統合テストが成功。
- 追加SQLを2回適用してもAppStateのハッシュと各専用テーブルの件数が変わらないことを確認。
- Linuxでは既存と新機能を合わせて133件が成功、隔離環境専用3件はスキップ。追加のR2 SDKテスト1件も成功。
- 学習20件・コンテスト16件・日英表示6件、lint・型チェック・本番向けビルドが成功。
- 今回の新機能について、ブラウザの手動操作・本番反映は未実施。本番DB・既存R2データは変更していません。

テスト用React rendererは非推奨警告を表示しますが、アプリの実行処理には使用しません。既存依存関係のnpm audit警告の解消は今回の範囲外です。
