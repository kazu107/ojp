# Japanese / English UI

## Behavior

- The header offers Japanese and English. The default is Japanese; sign-in is not required.
- `ojp_locale` stores the selection for one year, with Path `/`, HttpOnly, SameSite=Lax and Secure in production. Unsupported values fall back to Japanese.
- Switching updates React context immediately and saves the cookie through a validated server action. Next.js refreshes server-rendered labels and metadata without replacing client form state. If persistence fails, the previous selection is restored and a localized error is shown.
- Navigation, reloads and new tabs on the same origin use the saved selection. The HTML `lang`, metadata, accessibility labels and CodeMirror search controls follow the selected locale.
- When BroadcastChannel is available, other open tabs receive the saved preference and refresh their server labels while preserving client drafts. Without it, reloading the other tab applies the cookie.
- Dates use the selected locale and the Asia/Tokyo timezone in both server and client rendering.
- No database migration, environment variables, external translation services or per-language URL prefixes are needed. Deploy the updated application normally.

## Content Boundary

Translate interface labels, instructions, status labels, standard errors and progress messages. Do not translate authored problem statements, editorials, course/chapter/item titles, Markdown, quiz questions/options/explanations, sample content, display names, code, stdout or stderr. Their stored values, IDs and ZIP formats are unchanged. AC/WA/WJ and language names remain technical labels. Unknown diagnostics retain their original detail.

Learning headings now use the usual page-title/panel-title styles, without the marketing eyebrow. The Python first-download disclaimer is no longer displayed beside runnable cells; runtime behavior and safety limits are unchanged and remain documented in `learning-mode.md`.

Runnable Markdown uses a module-level renderer and a context for cell settings. Locale/server refreshes do not replace code cells or interrupt an active run, including in editor previews that do not use localStorage.

## Maintenance

`lib/i18n/messages.json` maps each canonical message to `ja` and `en`. Use `t("message", { namedParameter: value })` and put the whole sentence in the catalog, rather than concatenating translated fragments when word order differs. Insert user-authored values as parameters without translating those values.

- Server components: `const { t, locale } = await getI18n()` from `lib/i18n/server.ts`.
- Client components: `const { t, locale } = useI18n()` from `components/i18n-provider.tsx`.
- Module-level loading fallbacks: `UiText` reads the same context.
- Do not use translations as form values, enum comparisons, persistent IDs, API request data or React keys. Do not key editors by locale or reset drafts when locale changes.

The shared translator preserves whitespace, restricts catalog lookups to own properties and performs literal interpolation. A small explicit set of structured validation/progress messages is recognized; arbitrary user content is never automatically translated.

## Verification

```powershell
npm run test:i18n
npm run lint
npx tsc --noEmit
$env:STORE_DB_SYNC = '0'
npm run build
```

The unit suite checks both locales, interpolation parity, whitespace, fallback diagnostics, dates and catalog coverage for static UI text. HTTP integration tests are opt-in and restricted to the disposable local validation server, with a dummy authentication secret; never run them against production:

```powershell
$env:I18N_HTTP_TEST_ORIGIN = 'http://127.0.0.1:3100'
npm run test:i18n:http
```

The validation server must use `STORE_DB_SYNC=0`, `LEARNING_STORAGE=db`, `AUTH_SECRET=learning-local-validation-only-not-production`, `ADMIN_GITHUB_LOGINS=learning-test` and a separate local `ojp_learning_test` database. Do not replace the normal application's credentials with these values.
