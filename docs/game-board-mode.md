# ゲーム問題・盤面ビジュアライザー

## 実装した範囲

単人の盤面ゲームをコードで操作し、公開盤面での試走、正式提出、数値採点、リプレイ、学習課題への関連付けまで扱います。
`/games` がゲーム一覧、`/games/:problemId` が盤面とコードを並べるプレイ画面です。既存の問題詳細・提出画面も利用できます。

- 内蔵ゲームは迷路ロボットと宝集め。壁への移動、盤外移動、不明な命令、ゴール未到達、ターン超過は失敗です。
- 正式採点は既存のヒューリスティック用ジョブ・固定された問題版を使用し、通常のジャッジキューには重複登録しません。
- 正式提出の非公開ケースの盤面・リプレイは配信しません。公開ケースの試走と正式提出は別です。
- 学習の完了は本人の正式なAC提出で検証し、試走の成功では完了しません。
- Bot同士の対戦、マッチング、リーグ、ゲーム別レーティング、任意コードで書いたゲームエンジンの登録は未実装です。
- 試走結果は完了後に取得します。実行中のフレーム逐次配信は行いません。

## 作問

問題作成の「テストケース」でジャッジ方式をヒューリスティック採点、ビジュアライザーを盤面にします。
「内蔵の盤面ゲームを有効にする」で目標、入出力形式、ターン数、時間を設定できます。
壁・プレイヤー・ゴール・アイテムの記号と、各記号の色・表示文字・形を編集できます。床は `.` です。
盤面データは先頭行に `H W`、続けてH行の文字列を指定します。座標は左上が `(0,0)` です。

```text
5 8
########
#S..o.G#
#.#.#..#
#......#
########
```

プレビューの入力は、そのままではサンプル・テストケースを変更しません。
「最初の公開サンプルに反映」で下書きの先頭サンプルへコピーし、問題を作成・更新すると保存されます。
非公開テストの盤面は従来どおりグループ・ケースの入力欄で設定します。`.out` は不要です。
設定はZIPの `config.json` 内の `heuristic.board` と `heuristic.game` に入り、ブラウザ／サーバーのインポート、遅延編集、ZIPダウンロードで往復できます。

ゲームの判定は内蔵のversion 1ルールで行い、checkerのソースは実行しません。エディターではその欄を隠します。
ZIP形式との互換用に `checker/Main.js` のコメントだけのファイルを同梱します。生成スクリプトは必要なファイルをすべて作成します。

```powershell
npm run template:game-zip
```

`recovered/grid-game-examples` に迷路／宝集めと命令列／ターン制の組合せ4種類を作成します。
各ZIPは公開サンプル1件、暫定3ケース、最終3ケースで、Pythonの参考解答と独立したBFSによる最適値JSONも生成します。
既存ファイルは上書きしません。生成した例を明示的に上書きするときだけ `--force` を使用してください。

## ターン制

各ターン、提出には次のヘッダーとH行の盤面を渡します。盤面には現在のプレイヤー位置ではなく床を表示し、位置はヘッダーのx・yで渡します。
取得済みの宝は床になります。

```text
H W turn maxTurns x y
...H行の盤面...
```

提出は `UP` / `DOWN` / `LEFT` / `RIGHT` / `WAIT` / `STOP` のいずれか1つを改行付きで出力し、flushします。
終了時に `END` の1行を渡し、標準入力を閉じます。提出は終了しなければならず、750ms後も残るプロセスはREです。
初回は3秒、通常ターンは1秒の壁時計時間が既定です。ゲーム全体のCPU時間には問題の実行時間制限を適用し、全体の壁時計時間も最大60秒に制限します。
メモリ・プロセス数・作業領域・出力量の制限も適用します。ターン通信は最大64KiBです。
12言語の実行基盤を利用でき、11言語にはターン制の開始コードがあります。Brainfuckは入力処理の自作が必要です。

命令列形式では最初の盤面 `H W` とH行を渡し、提出が移動命令を空白または改行でまとめて出力します。こちらには全12言語の開始コードがあります。

## 採点・再現性

ゴールへ到達した場合の生スコアは次のとおりで、大きいほど良い評価です。

```text
迷路:   100000 + maxTurns - 実際のターン数
宝集め: 100000 + 取得した宝の数 * 1000 + maxTurns - 実際のターン数
```

宝集めでも出口への到達が必要です。ゴールへ到達すると終了し、その後の命令は採点対象にしません。
失敗ケースは既存のcase_zero／submission_zero規則に従います。複数ケースの合計・平均、相対評価、最終テストは既存のヒューリスティック採点を利用します。
ゲームルールは `heuristic.game.version: 1`、盤面形式は `heuristic.board.version: 1` です。
コンテストの固定版にはルール・表示設定・パッケージを含め、後から編集してもそのコンテストの試走・判定には固定版を使います。

## 汎用の盤面表示

内蔵ゲームを使わず、盤面表示だけをカスタムcheckerと組み合わせることもできます。
表示はマス、円、ひし形、文字、駒、経路に限定し、ユーザーが登録したJavaScript・HTML・URL・CSSは実行しません。
将棋やオセロ風の盤面を描画することと、その合法手・勝敗の判定は別です。独自のルール判定は別途必要です。

出力に次のJSONを与えると、複数の駒・経路をコマごとに表示できます。`board` の省略時は元の盤面を使います。
`cleared` は床へ変える座標の差分、`paths` はそのコマに表示する経路です。

```json
{
  "frames": [
    { "pieces": [{ "id": "robot", "x": 1, "y": 1, "glyph": "R", "color": "#f3a45d" }] },
    {
      "label": "step 1",
      "pieces": [{ "id": "robot", "x": 2, "y": 1, "glyph": "R", "color": "#f3a45d" }],
      "cleared": [{ "x": 2, "y": 1 }],
      "paths": [[{ "x": 1, "y": 1 }, { "x": 2, "y": 1 }]]
    }
  ]
}
```

盤面は最大32×32、記号32種類、各コマの駒128個、501コマ、JSONは256KiB、描画要素合計65536までです。
一時停止・コマ送り・速度・拡大・座標・経路表示、別の出力との比較に対応します。
再生はブラウザ内で行います。色は6桁の16進数だけを許可し、文字はReactでエスケープします。

## サーバー実行の有効化

既存のbasic sandboxだけで、新しいゲーム実行を公開することはしません。
サーバー実行には、必要なLinux機能が使える隔離workerが前提です。

```text
JUDGE_SANDBOX=bubblewrap
GAME_EXECUTION_ENABLED=1
```

`GAME_EXECUTION_ENABLED` はWeb側の試走・提出受付に使用します。workerは実際のsandboxも確認し、basicでの本番ゲーム実行を拒否します。
共有キューを読むworkerは、ゲーム有効化前にすべて同じ対応バージョン・隔離設定へ揃えてください。basic workerと隔離workerの混在ルーティングは未対応です。移設時は旧Heroku workerを停止してから新しいworkerへ切り替えます。
テストプロセスだけは `NODE_ENV=test` と `OJP_GAME_UNSAFE_LOCAL_TEST=1` の両方でbasicを許可します。この例外は `NODE_ENV=production` では使用できません。
本番のContaboでは、Webと同じコミットの非root隔離workerを使用します。workerはsystemdでCPU・メモリ・プロセス数を制限し、提出コードはbubblewrap内で実行します。
新規リリースの有効化前に、同じworker構成と検証用DBで試走・正式提出・最終テストを確認してください。ファイル・ネットワーク隔離だけでは資源の上限は保証されません。

試走は認証済みの有効ユーザーだけが実行できます。利用者ごとに同時2件、1分6件までです。
既存の `PackageJob` に公開設定と利用者が指定した盤面だけをスナップショットし、workerで実行します。非公開ZIPの参照を試走ジョブへ渡しません。
試走結果は本人・管理者だけが取得でき、既存の正式ジャッジの結果とは別に保持します。
小容量の試走リプレイはジョブの結果JSONに保存します。長期・大容量リプレイのR2分割保存は未実装です。問題ZIPのR2保存は既存機能を利用します。
新規DBテーブル・カラム・SQLマイグレーションは不要です。

## 検証

```powershell
npm run test:game
npm run test:i18n
npm run test:workspace
npm run build
```

HTTP統合テストは使い捨てのlocalhost `ojp_game_test` と `GAME_TEST_ORIGIN=http://127.0.0.1:3108` だけを許可します。
